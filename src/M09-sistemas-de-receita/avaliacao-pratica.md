# Avaliação Prática — Módulo 9: Sistemas de Receita Recorrente

## Objetivo da Avaliação

Ao concluir este módulo, o aluno não apenas entendeu a lógica da receita recorrente — ele tem uma oferta real, precificada e pronta para ser apresentada a clientes.

Esta avaliação é prática, não teórica. Você não passa por responder perguntas corretas. Você passa por entregar uma oferta recorrente estruturada e por apresentá-la para pelo menos 3 pessoas reais.

---

## Parte 1 — Construção do Pacote Recorrente

### Tarefa 1.1 — Documento do Pacote

Crie um documento (Google Docs, Notion ou similar) com seu pacote recorrente completo. O documento deve conter:

**Critérios obrigatórios:**

- [ ] Nome do pacote (não técnico — comunica resultado)
- [ ] Descrição em uma frase do que o serviço faz pelo cliente
- [ ] Para quem é (tipo de cliente, setor, porte)
- [ ] Lista detalhada do que está incluído (mínimo 5 itens específicos)
- [ ] Lista do que NÃO está incluído (mínimo 3 itens)
- [ ] Formato de entrega (como o cliente recebe o que foi feito)
- [ ] Relatório mensal: quais dados serão reportados
- [ ] Frequência e formato das reuniões
- [ ] Preço mensal definido
- [ ] Prazo mínimo de contrato (recomendado: 3 a 6 meses)

**Critério de aprovação:** Todos os 10 itens preenchidos, sem itens vagos como "e outras coisas" ou "suporte geral".

---

### Tarefa 1.2 — Cálculo do Ticket Mínimo Viável

Apresente o cálculo documentado:

- [ ] Estimativa de horas por cliente por mês (com detalhamento das atividades)
- [ ] Valor-hora escolhido e justificativa
- [ ] Custos de ferramentas e operação rateados
- [ ] Reserva de 15% calculada
- [ ] Ticket mínimo resultante
- [ ] Comparação com o preço final escolhido (preço final deve ser igual ou superior ao mínimo)

**Critério de aprovação:** Cálculo documentado mostrando que o preço final cobre o ticket mínimo.

---

### Tarefa 1.3 — Três Níveis de Preço

- [ ] Plano Essencial com escopo reduzido e preço menor
- [ ] Plano Profissional (o recomendado) com escopo completo
- [ ] Plano Premium com escopo expandido e preço maior
- [ ] Diferença clara entre os três em termos de entrega

**Critério de aprovação:** Os três planos devem ser genuinamente diferentes em escopo — não apenas em preço.

---

## Parte 2 — Argumentação de Venda

### Tarefa 2.1 — Âncoras de Preço

Escreva três frases de âncora específicas para o seu pacote:

- [ ] Âncora do custo de não ter o serviço
- [ ] Âncora do custo de contratar internamente (CLT equivalente)
- [ ] Âncora do ROI esperado (resultado possível / quanto o serviço se paga)

**Critério de aprovação:** Frases específicas para o seu serviço, não genéricas. "Contratar um funcionário CLT para fazer isso custaria R$ X/mês em encargos" é específico. "É muito mais barato do que a alternativa" é genérico.

---

### Tarefa 2.2 — Resposta a Objeções

Escreva respostas escritas para as 5 objeções mais comuns:

- [ ] "Está caro."
- [ ] "Preciso pensar."
- [ ] "Já tentei isso antes e não funcionou."
- [ ] "Prefiro fazer eu mesmo."
- [ ] "Não estou pronto para contratar agora."

As respostas não devem ser defensivas — devem mostrar compreensão e redirecionar para o valor.

**Critério de aprovação:** Cada resposta tem mais de 3 linhas, demonstra entendimento da objeção e apresenta um argumento concreto.

---

### Tarefa 2.3 — Apresentação de 3 Minutos

Escreva (e ensaie) uma apresentação verbal do seu pacote que dure 3 minutos. Deve cobrir:

- [ ] Quem é você e o que você faz especificamente
- [ ] Para quem o serviço é ideal
- [ ] O que está incluído (versão resumida)
- [ ] Um resultado que você já entregou ou que é possível esperar
- [ ] O preço e como funciona a contratação

**Critério de aprovação:** Texto escrito com no mínimo 200 palavras + evidência de que você ensaiou (pode ser anotação de quando foi cronometrado ou feedback de alguém que ouviu).

---

## Parte 3 — Evidência de Entrega

### Tarefa 3.1 — Modelo de Relatório Mensal

Crie um modelo de relatório mensal que você usaria com clientes. Pode ser um template no Google Slides, Canva, Google Docs ou Notion.

O relatório deve conter:

- [ ] Cabeçalho com nome do cliente, mês de referência e data
- [ ] Resumo executivo (3-5 linhas sobre o mês)
- [ ] Seção de entregas realizadas
- [ ] Seção de métricas e dados (com espaços para preencher os números)
- [ ] Seção de análise (o que os dados significam)
- [ ] Seção de próximos passos / plano para o próximo mês
- [ ] Rodapé com seu nome e contato

**Critério de aprovação:** Relatório visualmente organizado, em linguagem simples (sem jargão técnico), que um dono de pequena empresa consegue entender sem explicação.

---

### Tarefa 3.2 — Plano de Automação

Liste as 3 principais automações que você vai implementar para escalar o seu serviço:

Para cada automação:
- [ ] O que ela faz
- [ ] Ferramenta que vai usar
- [ ] Estimativa de horas economizadas por mês por cliente

**Critério de aprovação:** As 3 automações listadas devem ser ferramentas reais (com nome), não vagas.

---

## Parte 4 — Ação no Mundo Real

Esta é a parte que diferencia quem tem oferta de quem faz negócio.

### Tarefa 4.1 — Lista de Prospects

- [ ] Crie uma lista com no mínimo 10 nomes de pessoas que poderiam contratar o seu serviço
- [ ] Para cada nome, anote: nome completo, tipo de negócio, como você conhece, canal de contato

**Critério de aprovação:** Lista preenchida, com pessoas reais e identificáveis.

---

### Tarefa 4.2 — Apresentação para 3 Pessoas Reais

Esta é a tarefa final e inegociável do módulo.

Apresente sua oferta recorrente para pelo menos 3 pessoas que poderiam ser clientes. Não precisa ser uma venda — precisa ser uma conversa real sobre o que você oferece e se faz sentido para elas.

Para cada conversa, documente:

- [ ] Nome da pessoa e tipo de negócio
- [ ] Data da conversa
- [ ] Canal (presencial, telefone, WhatsApp, videochamada)
- [ ] O que você apresentou
- [ ] Qual foi a reação / resposta
- [ ] Próximo passo combinado (se houver)

**Critério de aprovação:** 3 conversas documentadas. A pessoa não precisa ter contratado. Precisa ter ouvido a oferta e dado alguma resposta (positiva, negativa ou de interesse futuro).

---

## Critérios de Aprovação do Módulo

Para concluir o Módulo 9 com aprovação:

| Tarefa | Aprovação |
|--------|-----------|
| 1.1 — Documento do pacote | Todos os 10 itens preenchidos e específicos |
| 1.2 — Ticket mínimo | Cálculo documentado, preço ≥ mínimo |
| 1.3 — Três níveis | Diferença real de escopo entre os níveis |
| 2.1 — Âncoras | 3 frases específicas, não genéricas |
| 2.2 — Objeções | 5 respostas com mais de 3 linhas cada |
| 2.3 — Apresentação | Texto + evidência de ensaio |
| 3.1 — Relatório | Modelo funcional em linguagem simples |
| 3.2 — Automações | 3 automações com ferramentas reais |
| 4.1 — Lista | 10 nomes com dados completos |
| 4.2 — Conversas | 3 conversas reais documentadas |

**Aprovação final:** 9 de 10 tarefas concluídas com os critérios acima. A tarefa 4.2 (3 conversas reais) é obrigatória — sem ela, o módulo não está concluído.

---

## Nota Final

Terminar este módulo com uma oferta na gaveta e nenhuma conversa real não é terminar o módulo. É acumular conhecimento sem aplicação.

O objetivo do MAEXTRO não é fazer você saber sobre negócio. É fazer você ter um negócio.

A primeira venda é a mais difícil. A segunda é mais fácil. A décima é natural.

Comece pelo primeiro passo: converse com alguém hoje.
